# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Connect 4 minimax / alpha-beta engine, a benchmark harness for it, and teaching material: a README with heuristic diagrams and lab exercises for an undergraduate course. Plain HTML/CSS/JavaScript with no dependencies, no build step, no package.json, no test suite and no linter.

## Commands

```bash
# Browser UI (game + Benchmark tab): just open the file
xdg-open index.html

# Benchmarks -> Markdown on stdout (progress goes to stderr)
node bench-cli.js --quick                                         # smoke test, a few seconds
node bench-cli.js --games 40 --max-depth 6 --rr-depth 4 > RESULTS.md   # how RESULTS.md was produced (~16 s)
# other flags: --opening <plies> (default 2), --seed <n> (default 42)
# note: CLI defaults (games 20, max-depth 5, rr-depth 3) differ from the RESULTS.md run

# Student lab runner (round robin of C4.HEURISTICS.mine vs three built-ins)
node lab-run.js [depth=4] [gamesPerPair=40] [seed=1] [search=alphabeta|minimax]

# Regenerate README diagrams from the engine
node docs/make-diagrams.js
```

`node bench-cli.js --quick` is the closest thing to a test. Its "Same value" column must read `yes` at every depth; a `NO` means alpha-beta or move ordering changed the minimax value.

## Architecture

**One engine, three consumers.** `engine.js` is a UMD module: it exports `C4` as `window.C4` in the browser and as `module.exports` in Node. `bench.js` wraps it the same way (`Bench`). The browser loads `engine.js` → `bench.js` → `app.js` via `<script>` tags. `bench-cli.js`, `lab-run.js` and `docs/make-diagrams.js` `require` them. Keep both files loadable in both environments, in the existing ES5 style (`var`, function expressions). The README targets Node 10+.

**Board conventions.** `cells` is an `Int8Array(42)` indexed `row*7 + col`. Row 0 is the **top** and pieces fall towards row 5, so the cell below `i` is `i + 7`. Values are 0 (empty), 1 (first player) and 2 (second player). `State` is mutable, with `play(c)`/`undo()` for search. `play` returns the landed cell index, which `isWinAt(idx)` checks.

**Heuristic contract.** `C4.HEURISTICS[key] = { label, formula, description, fn(cells, me) }`.
- Search scores terminal positions itself, as ±(1e9 + remaining depth) so faster wins rank higher, and calls `fn` only on non-terminal leaves. As a result, F4/O4 terms never fire, and heuristic values must stay far below 1e9.
- `fn` does not receive the side to move.
- Most built-ins come from `windowHeuristic(weights, cellBonus)`. It walks the 69 precomputed 4-cell windows (`C4.windows`) and looks up weights keyed by the string `'<my count><opp count>'`, e.g. `{ '30': 5, '03': -4 }`.
- Any key added to `HEURISTICS` automatically appears in the UI menus and the Benchmark tab (`app.js` iterates `Object.keys`), and as a new row in every `bench-cli.js` table.

**Search.** `chooseMove(st, opts)` shuffles the root moves with `opts.rand` and takes the first strict maximum, which gives a uniform random tie-break. `opts.exactRoot` searches every root move with a full window, so all 7 column scores are exact; the UI uses this to display them. Move ordering is either `CENTER_ORDER` or left-to-right; there is no transposition table or iterative deepening.

**Benchmarks.**
- Every runner in `bench.js` is `async` and yields with `setTimeout(0)` so the browser stays responsive. All randomness comes from seeded `C4.rng` (mulberry32), so runs are reproducible.
- `tournament` plays each random opening twice with colours swapped.
- `gauntlet` is a tournament with every agent paired against one reference agent; the depth sweep in `bench-cli.js` uses it.
- `searchBenchmark` compares minimax, alpha-beta and alpha-beta with ordering on the same sampled positions.

## Docs and teaching material: keep them in sync

- `docs/*.svg` are generated by `docs/make-diagrams.js` from the example position `3236434324`. The script throws if the cell-table or windows+center formulas no longer match the engine. Rerun it after changing any built-in heuristic.
- `README.md` contains hand-copied numbers that are **not** regenerated: the heuristic summary table (scores on the example, N=1 move choices, round-robin percentages from `RESULTS.md`), the Lab 1 answer key (position `3324452`), and the `lab-run.js` timing. Update them when the engine, the heuristics or `RESULTS.md` change.
- `my-heuristics.js` and `lab-run.js` are the student starter files. `my-heuristics.js` defines `C4.features` and registers `HEURISTICS.mine`; the README Setup section quotes its `fn`. It is deliberately **not** loaded by `index.html` (students add the script tag themselves) and not loaded by `bench-cli.js`.
